# MVP scope and priority contract

This document prevents feature sprawl. A feature is not P0 merely because it is impressive.

## P0 — submission/demo must be excellent

- one linear learning path and two complete missions;
- Trust/Suspicious/Investigate + confidence before/after;
- 4–6 evidence actions per case;
- three-axis conclusion and `insufficient evidence`;
- bounded Socratic hints using curated case evidence;
- process XP and Evidence Receipt;
- basic profile/progress/streak that never punishes missed crisis days;
- Ukrainian and English UI shell;
- accessible media alternatives;
- demo mode independent of live third-party APIs;
- pilot/eval instrumentation;
- 3-minute pitch assets.

## P1 — only after P0 release candidate

- C2PA/Content Credentials mission;
- live Crossref/OpenAlex citation adapter;
- Google Fact Check query adapter;
- daily spaced booster;
- teacher/community pack mock and read-only cohort view;
- push notification opt-in;
- low-bandwidth download of a reviewed pack.

## P2 — post-submission platform roadmap

- partner authoring studio and approval workflow;
- multi-tenant organizations;
- full classroom assignment/analytics;
- audio/video forensic integrations;
- peer challenge creation with moderation;
- broad localization marketplace;
- social/friend features;
- service extraction, streaming pipelines, data warehouse.

## Explicitly rejected for MVP

- detector ensemble or custom model training;
- universal source/reputation score;
- political leaderboard;
- unbounded agentic browsing;
- raw user uploads retained by default;
- generative mission publication without human review;
- blockchain as a substitute for provenance standards;
- microservices/Kubernetes merely to appear scalable.

## Scope change rule

Adding P1/P2 requires: named owner, removed or completed equivalent effort, acceptance criteria, security/privacy note, and unanimous four-person decision recorded in the issue/ADR.
