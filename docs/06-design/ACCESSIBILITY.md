# Accessibility and inclusive design

## Release baseline

Target WCAG 2.2 AA for web and equivalent Flutter semantics/mobile practices. Automated checks are necessary but not sufficient.

## Core checks

- logical semantics/focus order; all actions named with role/state/result;
- full keyboard operation and visible focus; no gesture-only action;
- text resize 200%, display zoom and reflow without clipping;
- AA contrast; status never color-only; high-contrast/grayscale review;
- media alt text, captions and transcripts; do not embed essential text in images;
- reduced motion and no flashing; animation can be skipped;
- error identified in text and linked to field; focus moves predictably;
- 44×44 targets and sufficient spacing;
- screen reader tested on mission, investigation, conclusion and receipt;
- language metadata and Ukrainian pronunciation/expansion reviewed;
- offline/low-bandwidth alternatives preserve the learning objective.

## Cognitive/emotional inclusion

Plain language, short chunks, consistent layout, explain uncertainty, content warnings without spoilers, no timers in core learning, compassionate streak and safe exit. Avoid trauma exploitation in Ukraine/crisis missions.

## QA evidence

Record device/browser/screen reader, text scale, keyboard path, contrast tool, issues and screenshots. Accessibility defects on the core path are release blockers when they prevent completion or comprehension.
