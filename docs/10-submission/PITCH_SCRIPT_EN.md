# Pitch script and demo choreography

Target: a flexible 3-minute core that can be shortened to 90 seconds or expanded with Q&A.

## 0:00–0:20 — hook

“A convincing post can be false, but a real image can also be used in a false context. Young people do not need another magic truth button. They need a repeatable way to investigate.”

Show one scenario. Do not start with a title slide.

## 0:20–0:45 — problem

Explain the behaviour gap: content changes faster than lists of examples. State one sourced problem fact at most. Show its citation in the appendix, not as floating text.

## 0:45–1:35 — live learning loop

1. Make an initial prediction and confidence estimate.
2. Inspect origin, date, context, and corroboration.
3. Select evidence and explain the conclusion.
4. Update confidence.
5. Receive process-based feedback.

Narration: “The product does not reward the lucky guess. It rewards the investigation.”

## 1:35–1:55 — second case

Show the contrast case: authentic media placed in a misleading context. This proves that the concept is broader than AI-generated content detection.

## 1:55–2:20 — evidence

Report only completed validation: “[N] participants completed [task]; [N/N] found [feature]; the dominant failure was [finding]; we changed [decision].”

If no pilot is complete, say: “Our pilot protocol and success thresholds are ready; the next milestone is a supervised test with [audience].”

## 2:20–2:40 — responsible scale

Show how reviewed scenario packs, facilitator guidance, accessibility, and privacy boundaries support reuse. Avoid architecture detail unless asked.

## 2:40–3:00 — ask and close

“We are seeking [specific partner/support] to validate [specific outcome] with [specific audience]. Evidence Gym turns the moment of doubt into a habit of verification.”

## Demo safety rules

- Use a pinned build and locally available backup recording.
- Reset demo state before the session.
- Never type real participant data or production credentials.
- Do not depend on a live model response for the critical path.
- Keep one screenshot per demo step in the backup deck.
- If a feature fails, describe the tested behaviour; do not improvise a false claim.

## Rehearsal scorecard

| Criterion | Pass condition |
|---|---|
| Problem clarity | A new listener can restate the behaviour problem |
| Product clarity | The verification loop is visible, not merely described |
| Evidence honesty | Current results and future targets are clearly separated |
| Differentiation | The audience understands why this is not a truth detector |
| Timing | Core pitch finishes with at least 10 seconds of buffer |
| Accessibility | Text is readable and narration explains visual state |
| Ask | The requested next step is specific and feasible |
