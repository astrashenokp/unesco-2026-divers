# Submission pack

This folder turns the product documentation into a reviewable hackathon submission. It does not replace the current official application form: before submission, reconcile every field and limit with the official UNESCO page.

## Recommended order

1. Freeze the claims in the [evidence appendix](EVIDENCE_APPENDIX_TEMPLATE.md).
2. Fill the [English proposal template](PROPOSAL_TEMPLATE_EN.md).
3. Rehearse the [pitch script](PITCH_SCRIPT_EN.md) against the real demo.
4. Stress-test the story with [judge questions](JUDGE_QA.md).
5. Run the [submission checklist](SUBMISSION_CHECKLIST.md) with two reviewers.

## Submission rule

Every material claim must be one of:

- demonstrated in the current build;
- supported by a named source;
- clearly labelled as a target, hypothesis, projection, or future work.

Never present planned functionality, projected reach, or untested learning impact as a completed result.
