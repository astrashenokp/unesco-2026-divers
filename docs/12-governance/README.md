# Product and programme governance

Governance keeps claims, content, money, partnerships, and decisions reviewable as the project grows. It does not assign programming roles.

## Operating set

- [Open questions](OPEN_QUESTIONS.md): unresolved choices that can change scope or risk.
- [Decision log](DECISION_LOG.md): concise record of resolved non-architecture decisions.
- [Governance model](GOVERNANCE_MODEL.md): forums, rights, escalation, and records.
- [Content review](CONTENT_REVIEW_CHECKLIST.md) and [correction policy](CONTENT_CORRECTION_POLICY.md).
- [Legal readiness](LEGAL_READINESS.md), [license decision](LICENSE_DECISION.md), and root third-party notices.
- [Budget model](BUDGET_MODEL.md).
- [Partnership strategy](PARTNERSHIP_STRATEGY.md) and [outreach templates](PARTNER_OUTREACH_TEMPLATES.md).
- [Programme lifecycle](PROGRAM_LIFECYCLE.md): idea, discovery, pilot, launch, operation, scale, and sunset.

## Principle

The person proposing a change supplies the evidence and identifies affected users. Material claims, high-risk content, participant data, spending commitments, and public partnerships require an explicit recorded decision before action.
